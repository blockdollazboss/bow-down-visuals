# Part 1 — Operator knowledge base

## 1.0 How the KB is generated and maintained (the fix-lane map)

- **Generator, not hand-curation:** `artifacts/api-server/scripts/generate-operator-knowledge.mjs` builds `operator-knowledge.json` from code sources of truth: routes/components from `App.tsx`, access from `lib/public-routes.ts` `ROUTE_MATRIX`, names from `app-sidebar.tsx` resolved through `en.json`, desk modules from `src/lib/desks.ts`, guides from `src/guides/*.ts`, descriptions from en.json prose fields / `usePageTitle` meta / `data/features.ts` taglines / page `DESCRIPTION` constants (deepening pass, money-figure-free, 25–300 chars), prices from `src/lib/credit-costs.ts` `CREDIT_COSTS` (cross-checked against server `*_COST` constants via `SERVER_PRICE_LINKS`), packs from `routes/stripe-payments.ts` `PACK_MAP`, takeover offers from `lib/db` `*_OFFER` constants, song tiers from `routes/generate/music-audio.ts` `SONG_PRICE_TIERS`.
- **The only hand-kept data in the generator** is classification: `STAGE_RULES`/`SEGMENT_STAGE`, `EXCLUSIONS`, `FEATURE_PRICE_LINKS`, `TIERED_PRICE_LINKS`, `SERVER_PRICE_OVERRIDES` (currently empty), and **`DOCKED_FEATURES` (generator line 1038)** — the 17 declared tab/panel/mode surfaces that own no route (e.g. `smart-reframe`, `rtmp-ingest`, `morning-brief`, `email-automations`).
- **Runtime:** `operator-knowledge.ts` loads the JSON, builds the grounding block (`buildGrounding`/`formatFeatureFacts`) and the no-invention guard (`findInventedPrice` against `KNOWN_VB_FIGURES`/`KNOWN_DOLLAR_FIGURES`).
- **Tests:** `artifacts/api-server/src/lib/__tests__/operator-knowledge.test.ts` (56 tests, **all passing on this tree** — see §1.4 for why that does not clear the KB). It re-derives routes + page files and fails on anything neither in the KB nor excluded; pins the description-less allowlist (10 ids), description floor (≥209), price-source/registry==rail pins, song tiers, takeover offers, Stack-20 surfaces, Stack-25 corrections, and the Stack-26 open-world block.
- **Blind spot (root cause of K1/K3/K7):** the coverage derivation only sees **routes and page files**. Surfaces built as *components* — a desk docked into `/create` + `/branding-kit`, the World's native desks (`components/world/native/`, 51 files), an admin panel inside `world.tsx` — are invisible to both the generator and its "no silent gaps" test unless someone adds a `DOCKED_FEATURES` entry by hand. Every grand-push gap below is an instance of this one blind spot.
- **Regeneration is necessary but NOT sufficient** for most gaps, and is currently **unsafe to run blind**: a scratch regeneration on this tree (a) still produces **235 features** — no wallpaper/district/lock entry appears; (b) attaches wallpaper prices to the *host* entries (`create`, `branding-kit`, and by one-hop import bleed to every other Create panel and Branding tab entry) without naming the desk anywhere; (c) attaches the desk's **dead** `/api/generate-video` endpoint (plus `/:param`) to 7+ entries as if it were a real endpoint (see W2) — the desk must be fixed *before* regenerating, or the KB learns the dead path; (d) does fix K4 and K5 on its own (endpoint/price re-scan).

**Defects:**

**W1 — HIGH — The King's Set cannot be rendered or screensaved: relative asset URLs vs http(s)-only rails.**
`KINGS_SET` stills/loops are site-relative (`lib/kings-set.ts:38–39,52–53,66–67`: `"/wallpapers/kings-set-…"`). "Use this art" does `setCurrentArt(piece.stillUrl)` (`WallpapersDesk.tsx:517`) and "Use as screensaver" does `setVideoUrl(piece.loopUrl)` (`:533`) with **no absolutification anywhere in the desk** (no `location.origin` join). Both rails validate URLs with `httpUrlSchema` — `z.string().refine(isHttpUrl)` (`routes/wallpapers.ts:78–105`): `renderSchema.sourceUrl` and `screensaverSchema.videoUrl` reject the relative path with **400 "Invalid request."** before any charge or render. So the desk's promoted starter pack fails at *Render exact size*, *Make the whole set*, and *Render loop* — the user sees only the generic failure copy. (Plain Download works — same-origin `<a download>`.) Secondary symptom on the same path: the relative loop URL matches no option in the screensaver video `<select>`, so the picker and the preview state disagree. Fix shape: absolutify King's Set URLs at selection time (`new URL(piece.stillUrl, window.location.origin).href`) or teach the rails to accept same-origin relative paths — one place, both buttons.

**W2 — HIGH — Screensaver "Generate video" is a dead button: it calls an endpoint that does not exist.**
`generateVideo()` POSTs to `/api/generate-video` (`WallpapersDesk.tsx:346`) and polls `/api/generate-video/${taskId}` (`:366`). There is **no such route**: S27-73 removed its registry entry as "that endpoint never existed", and `routes/generate/__tests__/video-studio-rail-alignment.test.ts:187` pins `POST /generate-video` staying **404**. Every click therefore fails into `wallpapers.videoGenerateFailed`. Compounding it: with no registry entry and no `overrideCost`, `useConfirmedApi` shows **no confirmation and no spend toast**, yet the button is labelled "Generate video — 400 Visual Bucs" (`:1004`) — a priced promise wired to nothing. The real rail for this job is `/api/generate-runway-clip` (400 VB, registry `credit-costs.ts:57`; the pattern every other caller — MusicVideoTimeline, SceneStudio, the in-world CreateDesks — uses, including its `GET /:taskId` poll shape). Rewire the desk to it (body/poll shapes differ: the runway rail's request/response fields must be mapped, not just the URL string).

**W3 — MEDIUM — Clean theme pack: cancelling the second confirmation silently discards the first, already-paid render.**
`makePack()` (`WallpapersDesk.tsx:240–249`) calls `renderOne(phone)` then `renderOne(desktop)`; in clean mode each call opens its **own** 400 VB confirmation (`overrideCost: CLEAN_RENDER_COST`). If the user confirms the phone render (charged 400, rendered, saved server-side as a generation) and cancels the desktop confirmation, `renderOne` returns `null`, `makePack` returns early, and the paid phone render is **never added to `renders`, never put in the pack, and no message says it exists** — the desk's own state throws away a paid result (the file survives only in the user's generation history). The advertised "800 Visual Bucs" total is honest, but the flow should either confirm once for the pack (800) up front or keep a partially-built pack/render list on cancel.
